```bash
REGISTRY PULL myprovider;
```
> To view previous provider versions or to pull a specific provider version, see [here](https://stackql.io/docs/language-spec/registry).

<details>

<summary>Using different environment variables</summary>

To use different environment variables (instead of the defaults), use the `--auth` flag of the `stackql` program. For example:

```bash
AUTH='{ "myprovider": { "type": "bearer", "credentialsenvvar": "MY_OTHER_VAR" }}'
stackql shell --auth="${AUTH}"
```

or using PowerShell:

```powershell
$Auth = "{ 'myprovider': { 'type': 'bearer', 'credentialsenvvar': 'MY_OTHER_VAR' }}"
stackql.exe shell --auth=$Auth
```
</details>

### Estate inventory

```sql
SELECT id, name, state, region
FROM myprovider.services.services
ORDER BY region, name;
```

### Posture

```sql
SELECT name, json_extract(config, '$.setting') AS setting
FROM myprovider.services.services;
```

### Provisioning

```sql
INSERT INTO myprovider.secrets.secrets (name, value)
SELECT 'stackql-demo', 'value';

UPDATE myprovider.services.services
SET description = 'updated'
WHERE service_id = '<id>';

EXEC myprovider.services.services.restart
  @service_id = '<id>';

DELETE FROM myprovider.secrets.secrets
WHERE name = 'stackql-demo';
```

> `UPDATE` marshals every `SET` value as a string; `INSERT` and `EXEC` send typed JSON, and `EXEC` cannot carry a boolean.

### Cross-provider

```sql
SELECT 'myprovider' AS platform, name, state
FROM myprovider.services.services
UNION ALL
SELECT 'snowflake', name, state
FROM snowflake.warehouses.warehouses;
```
